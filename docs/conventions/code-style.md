# 코드 스타일

| 항목 | 규칙 |
| --- | --- |
| 스타일 | Kotlin 공식 코드 스타일(`kotlin.code.style=official`). 별도 포매터·린터 도구는 프로토타입 이후에 검토한다 |
| 식별자 | 클래스, 함수, 변수는 영어 |
| 주석 | 한국어. 코드만 봐도 아는 설명은 쓰지 않고 이유가 필요한 곳에만 쓴다 |
| KDoc | public API에만. 사용법을 한국어 명사구로 쓴다 |
| 문자열 | 사용자에게 보이는 문자열은 코드에 직접 쓰지 않는다 ([resources](resources.md)) |
| 매직 넘버 | 터치 영역, 거리, 시간 임계값은 이름 있는 상수로 둔다 |

## 코드 가독성

이름과 구조만으로 책임과 데이터 흐름이 보이게 쓴다. 자동 검사가 없으므로 변경 후 직접 점검한다.

| 대상 | 규칙 |
| --- | --- |
| 파라미터 | 둘 이상인 선언과 호출은 각 파라미터를 별도 줄에 쓰고 마지막 쉼표를 둔다. 중첩 호출도 들여쓰기와 줄바꿈으로 구조를 드러낸다 |
| Modifier 체인 | 연산자마다 한 줄씩. 한 줄에 두 개 이상 이어 붙이지 않는다 |
| 빈 줄 | Route, Screen, 컴포저블에서 인접한 UI 요소와 논리적으로 구분되는 블록 사이에 둔다. 상태 선언, 이벤트 처리, 화면 구성도 읽기 좋은 단위로 나눈다 |
| 람다 | 여러 줄이면 본문을 들여쓰고 상태 변경·조건 처리·UI 요소 사이를 빈 줄로 나눈다. 한 줄 람다는 간단한 동작에만 쓴다 |
| 크기 | 요소 간격과 위치는 패딩, 정렬, 레이아웃 구성으로 표현한다. 고정 너비·높이는 콘텐츠 크기나 weight로 안 될 때만 쓴다 |
| Screen 분리 | Screen은 흐름을 한눈에 읽을 수 있게 유지한다. 독립된 역할이 있는 UI는 결합도와 응집도를 판단해 `component/`로 분리하되, 파일 수를 늘리기 위한 분리는 하지 않는다 |
| 상태 읽기 | 실제로 쓰는 가장 작은 컴포저블에서 읽는다. 자주 바뀌는 값(스크롤, 실시간 위치)은 필요한 곳까지 읽기를 미룬다 |

```kotlin
Modifier
    .fillMaxWidth()
    .padding(horizontal = 16.dp)
    .clickable(onClick = onClick)
```
