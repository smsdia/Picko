# 개발 하네스

에이전트가 변경을 반복 가능하게 구현하고 검증하는 작업 루프다. 요구사항은 제품 명세가, 계층 규칙은 [ARCHITECTURE.md](ARCHITECTURE.md)가 단일 기준이다.

## 작업 루프

1. **정렬**: 요청의 대상, 변경하지 않을 범위, 완료 조건을 확인한다. 필요한 파일·도구·권한이 있는지 확인한다. 완료 조건이 모호하거나 제품 판단이 필요하면 구현 전에 묻는다.
2. **작은 변경**: 완료 조건을 만족하는 최소 변경을 만든다. 기존 패턴을 우선 쓴다.
3. **검증**: 변경 범위에 해당하는 검증 게이트를 실행한다. 모델의 자기 평가가 아니라 빌드, 테스트, 정적 분석 결과를 근거로 판단한다.
4. **기록**: 변경한 파일, 실행한 검증과 결과, 실행하지 못한 검증과 이유를 남긴다. 새 규칙이나 결정이 생기면 해당 기준 문서를 갱신한다.

## 완료·재시도·에스컬레이션

- **완료**: 완료 조건 충족, 적용되는 검증 게이트 모두 통과, 결과 기록.
- **재시도**: 실패 로그로 설명되는 새 원인 가설과 변경이 있을 때만 한다.
- **에스컬레이션**: 같은 검증이 새 증거 없이 두 번 실패하거나, 필요한 파일·도구·권한이 없거나, 제품·보안·되돌리기 어려운 판단이 필요하면 멈추고 증거와 필요한 결정을 제시한다.

## 검증 게이트

작업 완료를 말하기 전에 변경 범위에 해당하는 항목을 모두 통과해야 한다.

| 변경 범위 | 필수 검증 |
| --- | --- |
| 모든 Kotlin/Compose 코드 | `./gradlew testDebugUnitTest lintDebug assembleDebug` |
| ViewModel / UiState | 이벤트별 UiState 전이를 단위 테스트로 고정한다. 차량 데이터는 가짜 repository로 대체한다. |
| Kotlin/Compose 변경 후 | 변경한 파일을 직접 다시 읽고 [ARCHITECTURE.md](ARCHITECTURE.md)의 「코드 가독성」(파라미터 줄바꿈, 마지막 쉼표, Modifier 체인, 블록 사이 빈 줄)과 대조한다. |
| 구조 | 자동 검사는 아직 없다. 프로토타입 기간에는 변경 후 `data/vehicle` 밖의 Pleos SDK import와 계층 방향 위반을 직접 확인한다. |
| 차량 연동 동작 | Pleos Connect Emulator에서 직접 확인하고, 결과에 에뮬레이터 검증 여부를 기록한다. 하지 못했으면 이유를 적는다. |

릴리스 빌드, 커스텀 가독성 테스트 같은 추가 게이트는 실제 문제가 반복될 때 승격한다. 구조·네이밍 규칙의 자동 강제(Konsist 등)는 프로토타입 이후 점검한다.

## 권한과 승인

| 구분 | 작업 |
| --- | --- |
| 자유롭게 허용 | 파일 읽기와 검색, 이 저장소 안의 코드·문서 수정, `./gradlew` 빌드·테스트·lint 실행, 문서 조회 |
| 물어보고 진행 | 새 의존성 추가, Gradle·Manifest·권한 변경, `CLAUDE.md`와 `docs/` 규칙 문서 수정, 파일 삭제, 저장소 밖 파일 접근, 외부 서비스로 데이터를 보내는 작업 |
| 금지 | `local.properties`와 키·시크릿 값의 읽기·출력·커밋, 강제 푸시와 `reset --hard`/`clean -f`/`branch -D`/`checkout .`/`restore .`, 요청 없는 커밋·푸시, 요청 범위 밖의 대규모 리팩터링 |

"금지"는 문서가 아니라 하네스가 막는다. 설정은 `.claude/`에 있다.

- `.claude/hooks/block-dangerous-git.sh`: 위험한 git 명령을 PreToolUse 훅으로 차단한다.
- `.claude/settings.json`: `local.properties`, `.env`, `*.jks` 등 비밀값 파일 읽기를 deny하고, 일반 `git push`는 사용자가 요청한 경우에만 하며 매번 확인(ask)을 받는다.
- 이 설정 파일을 바꾸기 직전에는 사용자에게 확인한다.

## 스킬

프로젝트 전용 스킬은 아직 만들지 않는다. 같은 절차를 두 번 이상 반복했을 때 스킬로 승격한다. 후보: 새 기능 화면 추가(Route/Screen/ViewModel/Contract/Navigation 세트), Pleos SDK 래퍼 추가(`data/vehicle`의 repository, impl, fake, di 세트). 문서는 규칙, 스킬은 절차를 담는다.

## 불변 조건

- 코드와 문서는 저장소 안에서 확인 가능한 근거로 판단한다. 추측으로 SDK 동작이나 API 계약을 확정하지 않는다.
- 검증 실패를 무시하거나 약화하지 않는다.
- 같은 경계 위반이 반복되면 문서를 늘리지 말고 테스트나 lint로 승격한다.
- 요청 범위 밖의 정리·리팩터링은 별도 변경으로 분리한다.
- 외부 시스템 변경, 비밀값 접근, 되돌리기 어려운 작업은 권한과 승인을 확인한 뒤 수행한다.

## 실행 경로

기본은 한 에이전트가 루프를 끝까지 수행하는 순차 실행이다. 사용자가 요청했고 하위 작업이 서로 독립적일 때만 병렬로 분리한다.
